# Farmora

Flutter/Firebase agricultural procurement marketplace for buyers, suppliers and logistics providers. The starter counter app has been replaced with a real-data application. No sample listings, completed sales or verification badges are fabricated.

## Implemented source

- Three primary tabs: Home, Messages, Profile; dashboards selected from persisted account role.
- Email registration/login/reset, persistent sessions, incomplete-profile recovery, role tutorial and consent draft.
- Products, buying requests and vehicles: image selection/upload, validation, publishing, editing, pausing and deletion; Firestore browsing, category filters, loaded-result search, pagination and refresh.
- Product quantity/subtotal, supplier identity, saved products, supplier offers and quotation requests.
- Server-controlled quotations, transactional stock reservation/restoration, idempotent order requests, delivery transitions and disputes.
- Transport job publication, capacity matching, quotations and assignment. Optional Google Routes road-distance estimates use provider vehicle rates. Estimates remain separate from accepted quotations.
- Real-time text conversations linked to marketplace records, unread counts, pagination, search, hide/block/report controls.
- In-app notifications, device registration, category settings and server FCM dispatch.
- External payment references awaiting administrator reconciliation. Clients cannot mark payments paid.
- Profile editing, support submission, account deletion restrictions, completed-order reviews.
- Separate Flutter web admin entry point with server-issued admin privilege checks, user verification/suspension, moderation, order inspection, dispute resolution and audited payment reconciliation.
- Firestore/Storage rules, indexes, configuration templates, unit/widget and emulator workflow tests.

## Local setup (Windows PowerShell)

The SDK found on this workstation is `C:\src\flutter`. Add its `bin` directory to PATH, or call the `.bat` files by full path. Run commands from this project unless indicated.

```powershell
flutter.bat pub get
flutter.bat analyze
flutter.bat test
cd functions
npm.cmd ci
npm.cmd test
cd ..
```

Use Node 22 for the deployed Functions runtime. A different local Node major may print an engine warning.

### Firebase emulator development

```powershell
cd functions
npm.cmd ci
cd ..
# Set JAVA_HOME to a Java 21+ installation if Java is not already on PATH.
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
# Local only: functions/.env.demo-farmora must contain ENFORCE_APP_CHECK=false.
functions\node_modules\.bin\firebase.cmd emulators:start --project demo-farmora
# In another terminal:
flutter.bat run -d chrome --dart-define-from-file=config/emulator.json
```

Android emulator uses `10.0.2.2` for the host; override `--dart-define=FIREBASE_EMULATOR_HOST=10.0.2.2`. A physical phone needs your computer's LAN address and reachable emulator ports. Emulator mode is rejected in release builds.

To run rules plus actual callable workflow tests against emulators:

```powershell
functions\node_modules\.bin\firebase.cmd emulators:exec --project demo-farmora --only auth,firestore,functions,storage "npm.cmd --prefix functions test"
```

Emulator-only test accounts and products are generated by the tests, not shipped in the marketplace.

## Connect a real Firebase project

1. Create/select your project, configure billing for Functions/Storage, choose the data region, and enable Email/Password Authentication.
2. Register Android and iOS apps. The current Android/iOS identifiers are starter identifiers: replace them with your chosen permanent application IDs before store registration.
3. Run FlutterFire configuration for the target apps. Add the matching Android `google-services.json` and Apple `GoogleService-Info.plist`, Firebase Gradle configuration and Apple capabilities. The runtime uses explicit FirebaseOptions, but native Messaging, Crashlytics and provider sign-in also require correct platform setup.
4. Copy `config/firebase.example.json` to an ignored `config/firebase.android.json`, `config/firebase.ios.json` or `config/firebase.web.json`, filling values from the corresponding registered Firebase app. Never use another platform's app ID. These are client configuration identifiers, not service-account credentials.
5. Register App Check: Play Integrity for Android, DeviceCheck for Apple, and a reCAPTCHA site key for web. Register debug tokens only for development. Functions enforce App Check by default; never deploy `ENFORCE_APP_CHECK=false` to production.
6. Deploy the backend with the Firebase CLI after logging into the intended project:

```powershell
functions\node_modules\.bin\firebase.cmd deploy --project YOUR_PROJECT_ID --only firestore,storage,functions
flutter.bat run --dart-define-from-file=config/firebase.android.json
```

7. Configure APNs signing/push capability on Apple, Android Firebase messaging, and web messaging/service-worker/VAPID setup if enabling browser push. Test actual delivery on each target device. Token registration alone does not prove delivery.
8. Crashlytics collection is enabled in release mobile builds; analytics is disabled until an approved consent flow is supplied.

Official setup references: [Flutter App Check](https://firebase.google.com/docs/app-check/flutter/default-providers), [Flutter App Check debug providers](https://firebase.google.com/docs/app-check/flutter/debug-provider).

### Maps and transport

The `estimateTransport` callable reads `GOOGLE_ROUTES_API_KEY` from the server environment. Enable Google Routes API and provision a restricted server key in the deployed service configuration; never put it in Dart defines or source. Without it, the app offers the real transport-quotation workflow and explains why no route estimate is available. Configure billing quotas and production request-rate limits before opening routing to users.

The calculation uses road distance from [Google Routes computeRoutes](https://developers.google.com/maps/documentation/routes/compute_route_directions), not straight-line distance: `base fee + road km * vehicle rate`. Provider service areas, tolls and handling require confirmation. Capacity matching currently requires matching units; it does not guess weight for crates, livestock or litres.

### Payments

Bank/mobile-money/cash references can be submitted for review. Administrators record verified payments/refunds with an audit reason. No live card/mobile-money gateway is configured. A gateway adapter must verify signed server webhooks before updating payment states. Clicking a button is never proof of payment; recording a refund does not execute a bank refund.

### Administrator app

```powershell
flutter.bat run -d chrome -t lib/admin/main.dart --dart-define-from-file=config/firebase.web.json
flutter.bat build web -t lib/admin/main.dart --dart-define-from-file=config/firebase.web.json
```

Create an administrator Auth account and grant `admin: true` using a trusted Admin SDK environment. No client UI can grant this claim. Sign in again after changing claims. Admin operations run through callables and produce audit records; ordinary Firestore rules do not grant bulk private-data reads to the mobile client. Host the built admin app behind an appropriate access policy. No admin app has been deployed by this implementation.

## Build instructions

```powershell
flutter.bat build apk --debug --dart-define-from-file=config/firebase.android.json
flutter.bat build appbundle --release --dart-define-from-file=config/firebase.android.json
# On macOS with Xcode, Apple signing and Firebase Apple setup:
flutter build ipa --release --dart-define-from-file=config/firebase.ios.json
```

The Android starter currently uses debug signing for release. Configure a private upload keystore and release signing before claiming Play readiness. Never commit signing secrets. iOS cannot be built or signed on this Windows machine.

## Structure and data

`lib/core`: initialization, repositories, roles, themes; `authentication`, `marketplace`, `messaging`, `orders`, `profile`, `admin`: feature screens; `shared`: reusable actions and identity widgets. Riverpod manages session/repository dependencies. Navigation uses Flutter routes within the fixed three-tab shell.

See [data model](docs/DATA_MODEL.md) and [launch gaps](docs/LAUNCH_GAPS.md). The source is an initial functional implementation, not a declaration of production readiness. External configuration and remaining product work are listed explicitly.

### Optional authentication providers

After enabling and configuring the provider in Firebase, set `ENABLE_GOOGLE_SIGN_IN=true` and (when required) `GOOGLE_SERVER_CLIENT_ID` in the platform configuration. Native Google authentication uses google_sign_in; web uses Firebase popup sign-in. Configure Android SHA fingerprints and the Apple reversed client ID URL scheme. Set `ENABLE_PHONE_SIGN_IN=true` only after enabling Phone Auth, SMS regions/quotas and platform verification. Test with Firebase test phone numbers first.

For slow Windows emulator startup set `FUNCTIONS_DISCOVERY_TIMEOUT=120` before running the Firebase CLI. The test suite must run sequentially because its security-rule suite clears its isolated demo database. The configured npm test script enforces this.
